# WORKFLOW — how llm-cache works, end to end

A plain walkthrough of what happens when you call `get_or_call`, which file does it, and which
function to open. Read this top to bottom once and you'll know the whole library.

Everything starts and ends in one method: **`LLMCache.get_or_call`** (`src/llm_cache/cache.py:53`).
Every other file exists to serve one of its five steps.

---

## 1. The file map

| File | Job in one line | Key names |
| --- | --- | --- |
| `cache.py` | The conductor. Runs the 5 steps below and owns the fallback rules. | `LLMCache.get_or_call` |
| `embeddings.py` | Turns text into a vector. | `SentenceTransformerEmbeddings.embed` |
| `redis_store.py` | Reads and writes Redis. Builds the cache key. | `RedisStore.add`, `.candidates`, `scope_id` |
| `connection.py` | Decides *which* Redis to talk to: one node, or Sentinel + replicas. | `build_endpoints`, `SentinelConfig`, `ReplicationConfig` |
| `similarity.py` | Compares vectors. Pure math, no I/O. | `cosine_similarity`, `best_match` |
| `models.py` | The two data shapes that move between the files. | `CacheEntry`, `CacheResult` |
| `stats.py` | Counts hits and misses in memory. | `CacheStats` |
| `cli.py` | Optional terminal command to peek at Redis. | `main` |

The dependency flow is one-directional — `cache.py` imports the other four, and they never import
each other or it:

```
                 cache.py
                /   |   \   \
               v    v    v   v
     embeddings  redis_store  similarity  stats
                     |
                     v
                  models.py
```

## 2. One call, step by step

```python
result = cache.get_or_call(prompt="Can you explain Docker?", llm=my_llm)
```

### Step 1 — Work out *which* cache to look in

`scope_id(model, temperature, system_prompt)` → `redis_store.py:32`

Before anything else, the config is hashed into a short string:

```python
scope = scope_id("gpt-4o-mini", 0.0, "You are terse.")  # -> "a3f9c21e8b04"
```

That hash becomes a segment of every Redis key:

```
llm-cache : my-app  : a3f9c21e8b04 : 7d2e...
   ^          ^            ^            ^
 prefix   namespace   config hash   entry id
```

**Why it matters:** answers generated by a different model or system prompt live under a
*different key pattern*, so they are never even looked at. This is how "changing the model must
not reuse the old answer" is enforced — not by comparing, but by never meeting.

### Step 2 — Turn the prompt into a vector

`LLMCache._embed` (`cache.py:133`) → `SentenceTransformerEmbeddings.embed` (`embeddings.py:42`)

```python
"Can you explain Docker?"  ->  [0.021, -0.134, 0.088, ...]   # 384 numbers
```

The model (`all-MiniLM-L6-v2`) is loaded lazily on the first call, inside `_load`
(`embeddings.py:35`), so importing the library stays fast.

`_embed` wraps this in a `try/except`. **If embedding fails it returns `None`**, and steps 3 and 5
are skipped entirely — see [Failure paths](#4-failure-paths).

### Step 3 — Look for a close enough match

`LLMCache._lookup` (`cache.py:141`), using two helpers:

1. **`RedisStore.candidates(scope)`** (`redis_store.py:113`) — runs a Redis `SCAN` over
   `llm-cache:<namespace>:<scope>:*`, loads each hash, and rebuilds it into a `CacheEntry` via
   `_entry_from_hash` (`redis_store.py:148`). Expired keys simply aren't there; Redis already
   deleted them.
2. **`best_match(query, candidates)`** (`similarity.py:29`) — scores the new vector against every
   candidate with `cosine_similarity` (`similarity.py:14`) and returns the single highest pair.

Then one comparison decides everything:

```python
if similarity >= self.similarity_threshold:  # cache.py:153
    return entry, similarity  # -> HIT
return None  # -> MISS
```

| similarity | threshold | outcome |
| --- | --- | --- |
| 0.95 | 0.90 | HIT — LLM never called |
| 0.72 | 0.90 | MISS — fall through to step 4 |

### Step 4a — HIT: return the cached answer

Back in `get_or_call` (`cache.py:74-85`): `self._stats.record_hit()`, then build a `CacheResult`
carrying the stored `response`, `similarity`, and the original `created_at` as `cached_at`.

**`llm` is never called.** That is the entire point of the library.

### Step 4b — MISS: call the LLM

`cache.py:87-88`:

```python
response = llm(prompt)  # your function — the library does not know or care who it calls
self._stats.record_miss()
```

`llm` is any `Callable[[str], str]`. There is no provider SDK anywhere in this codebase.

### Step 5 — Store the new answer (miss only)

`LLMCache._store` (`cache.py:157`) builds a `CacheEntry` (`models.py:26`) with a fresh
`uuid4` id, then calls `RedisStore.add` (`redis_store.py:87`), which:

- writes one Redis **hash** — prompt, response, metadata, and the embedding packed as raw
  `float32` bytes by `_encode` (`redis_store.py:54`);
- calls `EXPIRE` with the TTL, so **Redis deletes the entry itself** when it ages out. There is no
  cleanup thread anywhere in this library.

### And finally

A `CacheResult` (`models.py:10`) comes back either way:

```python
result.response  # str    — the answer
result.cache_hit  # bool   — True when no LLM call happened
result.similarity  # float|None — the winning score; None on a miss
result.latency_ms  # float  — measured by _elapsed_ms (cache.py:186)
result.cached_at  # datetime|None — when the entry was stored; None on a miss
```

## 3. The whole thing as a picture

```
get_or_call(prompt, llm)
        |
        v
[1] scope_id(model, temperature, system_prompt)      redis_store.py
        |                                            -> "which shelf?"
        v
[2] embeddings.embed(prompt)  ---- fails? ----+      embeddings.py
        |                                     |      -> "prompt as numbers"
        v                                     |
[3] store.candidates(scope)   ---- fails? ----+      redis_store.py  (Redis SCAN)
        |                                     |
    best_match(...)                           |      similarity.py   (pure math)
        |                                     |
   similarity >= threshold?                   |
        |                                     |
   yes -+------------------> [4a] HIT         |
        |                    stats.record_hit |
        |                    return cached    |
        |                                     |
   no --+------------------> [4b] MISS <------+   (both failures land here)
                              llm(prompt)
                              stats.record_miss
                                   |
                                   v
                             [5] store.add(entry)    (skipped if step 2 failed)
                                 EXPIRE key ttl
                                   |
                                   v
                              CacheResult
```

## 4. Failure paths

The rule the whole design bends around: **caching is an optimization, never a hard dependency.**
No cache failure escapes `get_or_call`.

| What breaks | Caught in | What happens | Result |
| --- | --- | --- | --- |
| Redis is down during lookup | `_lookup` (`cache.py:145`) | warning logged, treated as "no match" | LLM called normally |
| Redis is down during write | `_store` (`cache.py:182`) | warning logged, answer simply not cached | answer still returned |
| Embedding model fails | `_embed` (`cache.py:137`) | returns `None`; lookup **and** write skipped | LLM called normally |

All three log to the `llm_cache` logger and return `cache_hit=False`. The Redis errors are raised
as `RedisStoreError` (`redis_store.py:28`) by the store and caught by the cache — that's the only
exception type crossing the boundary.

## 5. Where to change things

| You want to... | Open |
| --- | --- |
| Change when a HIT is allowed | `cache.py:153`, or just pass `similarity_threshold=` |
| Use a different embedding model | `embeddings.py:12` (`DEFAULT_MODEL`), or pass `embeddings=` |
| Swap Redis for a real vector DB | Reimplement `add`, `candidates`, `ping`, `clear` in `redis_store.py:62` — nothing in `cache.py` needs to change |
| Add a field to cached entries | `CacheEntry` (`models.py:26`), then `add` and `_entry_from_hash` in `redis_store.py` |
| Change what `stats()` reports | `CacheStats.as_dict` (`stats.py:44`) |
| Change the Redis key layout | `RedisStore.key` / `.pattern` (`redis_store.py:74`) |

## 6. Swapping the pieces out

`LLMCache.__init__` (`cache.py:47`) accepts `embeddings=` and `store=`, and `RedisStore` accepts
any `client` implementing the handful of commands it uses. That is the seam for substituting
parts without touching the cache logic:

| Substitute | For | Example |
| --- | --- | --- |
| any object with `.embed(text)` | the embedding model | a hosted embedding API |
| any object with `hset`/`hgetall`/`scan_iter`/`expire`/`delete`/`wait`/`info` | the Redis client | an in-process dict, to run the cache with no Redis at all |
| any `Callable[[str], str]` | the LLM | a thin wrapper over any provider's HTTP API |

Roughly 80 lines of dict-backed stand-in is enough to run the whole cache with no Redis at
all, which is the clearest illustration that the seam is real.
